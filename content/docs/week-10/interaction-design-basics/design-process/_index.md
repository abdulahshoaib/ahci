# Design Process

The design process is used to create interactive systems that satisfy user needs and achieve design goals. It starts by identifying the difference between what currently exists and what users actually need.

## Requirements

Identify:

- What currently exists
- What users want
- Problems with existing systems
- Goals for the new system

Techniques include interviews, observation, and ethnography.

## Analysis

Organize and understand the gathered information.

Focus on:

- Understanding user needs
- Identifying problems
- Prioritizing requirements
- Understanding the context of use

## Design

Decide:

- What the system should do
- How it should work
- How users will interact with it

Designers use principles, guidelines, navigation structures, and interface designs to create solutions.

## Prototyping

Create an early version of the system to explore ideas and test designs.

Prototypes help:

- Test concepts
- Discover usability issues
- Collect feedback
- Reduce development risk

## Evaluation

Assess whether the design meets user needs and usability goals.

Methods include:

- User testing
- Heuristic evaluation
- Scenario-based evaluation

## Iteration

Design is iterative and rarely correct the first time.

The cycle is:

Requirements → Analysis → Design → Prototype → Evaluate → Redesign

Iteration helps improve the design and uncover additional requirements.

## Implementation and Deployment

Build and release the final system.

Activities include:

- Development
- Testing
- Documentation
- Help and support materials
- Deployment to users

## Design Trade-Offs

Design always involves trade-offs because time and resources are limited.

Common trade-offs include:

- Usability vs development effort
- Features vs simplicity
- Cost vs functionality

A good design solves the most important user problems within available constraints.
