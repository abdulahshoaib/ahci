# Index Card Prototyping

Index card prototyping is a low-fidelity prototyping technique that uses small paper cards to represent parts of a user interface or interaction.

Typically, standard index cards (3 × 5 inches) are used, with each card representing a single screen, menu, dialog box, or interaction element. By arranging and changing the cards, designers can simulate how users move through a system.

During evaluation, designers and stakeholders can step through the cards in sequence to demonstrate tasks and workflows.

## How It Works

1. Create individual cards representing interface elements or screens.
2. Arrange the cards in the order of interaction.
3. Ask users to perform a task.
4. Replace or move cards as the interaction progresses.
5. Observe user behavior and gather feedback.

## Characteristics

- Simple and inexpensive
- Easy to create and modify
- Supports rapid design changes
- Useful for early design exploration
- Requires no software or technical tools

## Benefits

- Encourages experimentation with different designs
- Helps visualize user workflows
- Allows quick testing of navigation structures
- Supports stakeholder participation
- Makes design problems easier to identify before implementation

## Example: Food Delivery App

| Card | Represents |
|--------|------------|
| Card 1 | Home screen |
| Card 2 | Restaurant list |
| Card 3 | Restaurant menu |
| Card 4 | Food item details |
| Card 5 | Checkout screen |
| Card 6 | Order confirmation |

A user starts with the Home Screen card. As they interact with the prototype, the designer presents the next card corresponding to the user's action, simulating navigation through the application.

## Example: ATM System

| Card | Represents |
|--------|------------|
| Card 1 | Welcome screen |
| Card 2 | PIN entry |
| Card 3 | Transaction menu |
| Card 4 | Withdrawal amount selection |
| Card 5 | Confirmation screen |
| Card 6 | Receipt and cash collection |

By stepping through these cards, designers can evaluate whether the interaction flow is logical and easy to understand before building the actual system.
