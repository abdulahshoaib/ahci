# Norman’s 7 Principles

Norman's 7 Principles provide practical guidance for designing systems that are easy to understand, easy to use, and resistant to user errors.

They focus on how users think, perceive, and interact with systems.

## 1. Use Both Knowledge in the World and Knowledge in the Head

Designs should combine what users already know with information provided by the system.

- Knowledge in the head: information users remember.
- Knowledge in the world: information visible in the interface.

Users should not be forced to remember everything.

### Examples

- Visible menu options
- Labels on buttons
- Tooltips and hints
- Navigation breadcrumbs

## 2. Simplify the Structure of Tasks

Complex tasks should be broken into smaller and more manageable steps.

This reduces cognitive load and makes tasks easier to complete.

### Example

Online checkout process:

1. Shopping Cart
2. Address Information
3. Payment
4. Confirmation

## 3. Make Things Visible: Bridge the Gulfs of Execution and Evaluation

Users should easily determine:

- What actions are possible (Gulf of Execution)
- What happened after an action (Gulf of Evaluation)

The system should clearly communicate available actions and current status.

### Examples

- Clearly labeled buttons
- Progress indicators
- Status messages
- Visual feedback after actions

## 4. Get the Mappings Right

Controls should have a natural relationship with their effects.

Users should be able to predict the outcome of an action.

### Examples

- Volume slider moving right increases volume
- Up arrow scrolls upward
- Light switch direction matches expected behavior

## 5. Exploit the Power of Constraints, Both Natural and Artificial

Constraints limit possible actions and help prevent errors.

Types of constraints include:

### Physical Constraints

Physically prevent incorrect actions.

**Example:**

- Disabled button cannot be clicked.

### Logical Constraints

Only valid options are available.

**Example:**

- Invalid dates cannot be selected in a date picker.

Good design prevents mistakes by restricting incorrect actions.

## 6. Design for Error

Assume users will make mistakes and design systems that support recovery.

Errors should be anticipated rather than ignored.

### Examples

- Undo functionality
- Confirmation dialogs
- Clear error messages
- Auto-save features
- Recovery options

Errors are normal; the interface should help users recover easily.

## 7. When All Else Fails, Standardize

Use established conventions and standards whenever possible.

Users already understand common interface patterns.

Designers should avoid reinventing familiar interactions without good reason.

### Examples

- Shopping cart icon for purchases
- Magnifying glass for search
- Hamburger menu for navigation
- Standard keyboard shortcuts
